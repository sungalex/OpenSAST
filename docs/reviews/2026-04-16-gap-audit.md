## 1. 당시 진단 요약

openSAST 는 2-Pass 파이프라인 · 6개 엔진 통합 · MOIS 49 카탈로그 · LLM Triage
원본 보존 원칙 · 플러그인 레지스트리 · 3-프로파일 설정 등 **구조적 완성도가 매우
높다**. 반면 실제 사용 가치를 결정짓는 **(1) YAML 룰 커버리지**,
**(2) 엔터프라이즈 운영 기반**(멀티테넌시/관측성/시크릿/컨테이너 보안),
**(3) 몇몇 파이프라인 결함**이 남아 있다.

### 1.1 당시 잘 된 부분

| 영역 | 위치 | 평가 |
|---|---|---|
| 2-Pass 파이프라인 | `orchestrator/pipeline.py` | `FIRST_PASS_ENGINES` / `SECOND_PASS_ENGINES` 분리 구조 명확 |
| MOIS 49 카탈로그 | `mois/catalog.py` | 49개 항목 전부 등록, CI 에서 개수 강제 |
| LLM Triage 원칙 | `llm/triage.py` | 원본 Finding 제거 금지를 주석+코드로 강제 |
| 플러그인 레지스트리 | `plugins/registry.py` | `Registry[T]` 제네릭, entry_points 자동 발견 |
| 3-프로파일 설정 | `config.py` | local/docker/cloud 기본값 + `validate_profile()` |
| RBAC + 계정 잠금 | `api/security.py` | bcrypt NFC 정규화, 문자 클래스 검증, 계정 잠금 |
| 리포트 4종 | `reports/` | SARIF / HTML / PDF / Excel, 한글 폰트 지원 |
| OS 매트릭스 CI | `.github/workflows/ci.yml` | Ubuntu/macOS/Windows × amd64/arm64 |

### 1.2 당시 핵심 약점

| 영역 | 문제 요지 |
|---|---|
| 룰 커버리지 | MOIS 49 중 13개만 매핑 (26.5%) |
| 엔터프라이즈 운영 기반 | 관측성 · 멀티테넌시 · 시크릿 관리 · 컨테이너 보안 부재 |
| 파이프라인 세부 결함 | severity 문자열 비교, 2nd pass 자동 비활성, 하드코딩 상수 |
| 엔진/워커 통합 테스트 | 모든 엔진이 MagicMock 뒤, Celery 도 MagicMock |
| 계획서 약속 미이행 | VS Code 확장 · GitLab CI · Jenkins 플러그인 · PR 통합 UI |
